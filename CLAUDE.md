# ocswitch

Расширение для Chrome и Firefox, переключающее трафик браузера через локальный
SOCKS5-прокси `127.0.0.1:11080`, за которым стоит личный сервер.

Туннель поднимается снаружи одной командой и живёт независимо от браузера:

    ssh -D 11080 -N user@admin.romancox.dev

Расширение туннель не запускает и не останавливает. Оно решает ровно одно:
какие запросы в него отправлять.

## Архитектура — не нарушать

- Вся логика маршрутизации живёт в `packages/core`.
  В `core` не может быть ни одного обращения к `chrome.*` или `browser.*`.
- `decide(host, settings)` — единственный источник истины.
  Любая новая логика идёт туда, а не в адаптеры расширений.
- Chrome получает решения через сгенерированный PAC-скрипт (`core/src/pac.ts`),
  потому что `chrome.proxy` не умеет иначе.
- Firefox вызывает `decide()` напрямую из `proxy.onRequest`. PAC там не нужен.
- Логика в PAC неизбежно дублирует `decide()`. Расхождение двух реализаций
  ловится тестом-близнецом в `packages/core/test/decide.test.ts`.
  Этот тест удалять нельзя.

## Правила

- TypeScript strict. Никакого `any` в `core`.
- Настройки только в `storage.local`. Никогда не `storage.sync` —
  список доменов не должен уезжать в облачный аккаунт.
- `localhost`, `127.0.0.1`, `::1`, `*.local` — всегда DIRECT, во всех режимах.
- В PAC всегда `SOCKS5` (не `SOCKS` — это SOCKS4, он резолвит DNS локально
  и создаёт утечку). В Firefox всегда `proxyDNS: true`.
- Правила матчатся только по хосту, не по пути: Chrome отдаёт в PAC
  только `scheme://host:port` для https.
- Никаких секретов и `.env` в git.

## Режимы

Взаимоисключающие, в UI это переключатель на четыре положения, а не тумблеры.

- `off`     — весь трафик напрямую, туннель игнорируется
- `all`     — весь трафик через прокси
- `include` — через прокси только хосты из списка
- `exclude` — через прокси всё, кроме хостов из списка
