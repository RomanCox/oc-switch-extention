# Приложения

Туннель уже поднят. Ниже — куда вписать прокси в каждом случае.

    SOCKS5   127.0.0.1:11080
    HTTP     127.0.0.1:11081

---

## Через VPN

### JetBrains — WebStorm, PyCharm, IDEA

Settings → Appearance & Behavior → System Settings → HTTP Proxy
→ Manual proxy configuration → **SOCKS**, host `127.0.0.1`, port `11080`.

Влияет на саму IDE: плагины, VCS, обновления, AI-функции.
На встроенный терминал НЕ влияет.

### Claude CLI

Через `claude\apply-settings.ps1` (Windows) или `claude/apply-settings.sh`
(Linux, macOS) — уже сделано на шаге 4. Работает в любом терминале,
включая терминал внутри IDE.

### Claude Desktop, Antigravity и другие Electron-приложения

Ключ управляет сетевым стеком Chromium. Запросы, которые приложение
делает из Node в основном процессе, идут мимо — насколько это важно
для конкретного приложения, покажет только проверка.

    --proxy-server="socks5://127.0.0.1:11080"

Windows: правый клик по ярлыку → Свойства → дописать ключ в конец поля
«Объект».

macOS: запускать из терминала —

    open -a "Claude" --args --proxy-server="socks5://127.0.0.1:11080"

Linux: дописать ключ в `Exec=` соответствующего `.desktop`-файла
(обычно `~/.local/share/applications/` или `/usr/share/applications/`),
либо запускать бинарник с этим флагом из терминала.

### Chrome и Firefox

Расширение ocswitch. Даёт то, чего не даёт ничто другое: выбор
по конкретному сайту, а не по приложению целиком.

### git

    git config --global http.proxy socks5h://127.0.0.1:11080

Буква `h` обязательна: без неё DNS резолвится локально и имена утекают
мимо туннеля.

Отключить:

    git config --global --unset http.proxy

### npm, pip, gh и прочее

Понимают `HTTPS_PROXY`. Ставить его в переменные среды пользователя
можно, но тогда через сервер пойдёт весь консольный трафик, включая
тот, которому это не нужно. Лучше точечно, в конкретной сессии:

Windows (PowerShell):

    $env:HTTPS_PROXY = 'http://127.0.0.1:11081'

Linux, macOS:

    export HTTPS_PROXY='http://127.0.0.1:11081'

## Мимо VPN

Ничего не настраивать. Системного VPN нет, прокси не прописан — трафик
идёт напрямую. Торрент-клиент, игры, всё остальное работают на полной
скорости домашнего канала.

---

## Чего туннель не умеет

`ssh -D` не поддерживает UDP. Через SOCKS5 ходит только TCP.

Для браузеров и IDE это незаметно: Chromium сам отключает QUIC при работе
через прокси. Но голосовые звонки, игры и всё остальное на UDP через этот
туннель не пойдут. Если понадобится — на сервер ставится полноценный
SOCKS5-сервер, умеющий UDP ASSOCIATE.
