# ocswitch

Расширение для Chrome и Firefox, переключающее трафик браузера через локальный
SOCKS5-прокси `127.0.0.1:11080`, за которым стоит личный сервер.

Туннель поднимается снаружи одной командой и живёт независимо от браузера:

    ssh -D 11080 -N user@admin.romancox.dev

Расширение туннель не запускает и не останавливает. Оно решает ровно одно:
какие запросы в него отправлять.

## Архитектура — не нарушать

- Вся логика маршрутизации живёт в `packages/core`.
  В `core` не может быть ни одного обращения к `chrome.*` или `browser.*`.
- `decide(host, settings)` — единственный источник истины.
  Любая новая логика идёт туда, а не в адаптеры расширений.
- Chrome получает решения через сгенерированный PAC-скрипт (`core/src/pac.ts`),
  потому что `chrome.proxy` не умеет иначе.
- Firefox вызывает `decide()` напрямую из `proxy.onRequest`. PAC там не нужен.
- Логика в PAC неизбежно дублирует `decide()`. Расхождение двух реализаций
  ловится тестом-близнецом в `packages/core/test/decide.test.ts`.
  Этот тест удалять нельзя.

## Правила

- TypeScript strict. Никакого `any` в `core`.
- Настройки только в `storage.local`. Никогда не `storage.sync` —
  список доменов не должен уезжать в облачный аккаунт (Google/Mozilla).
  Синхронизация между браузерами — только через собственный сервер
  (см. «Синхронизация» ниже), это другое: данные остаются у владельца.
- `localhost`, `127.0.0.1`, `::1`, `*.local` — всегда DIRECT, во всех режимах.
- В PAC всегда `SOCKS5` (не `SOCKS` — это SOCKS4, он резолвит DNS локально
  и создаёт утечку). В Firefox всегда `proxyDNS: true`.
- Правила матчатся только по хосту, не по пути: Chrome отдаёт в PAC
  только `scheme://host:port` для https.
- Никаких секретов и `.env` в git.

## Режимы

Взаимоисключающие, в UI это переключатель на четыре положения, а не тумблеры.

- `off`     — весь трафик напрямую, туннель игнорируется
- `all`     — весь трафик через прокси
- `include` — через прокси только хосты из списка `+VPN`
- `exclude` — через прокси всё, кроме хостов из списка `−VPN`

## Списки правил

Два независимых списка, у каждого правила — свой список (`list: 'proxy' | 'direct'`)
и своя сила (`strength: 'force' | 'soft'`):

- `+VPN` (`list: 'proxy'`) — хосты, которые должны идти через туннель.
- `−VPN` (`list: 'direct'`) — хосты, которые должны идти мимо туннеля.
- `soft` — правило участвует только в «своём» режиме: `+VPN` в `include`,
  `−VPN` в `exclude`. Вне этого режима хост ведёт себя как обычный,
  не из списка.
- `force` — правило побеждает в любом режиме, включая `off` (для `+VPN`)
  и `all` (для `−VPN`). Единственное, что сильнее force-правила —
  встроенный `ALWAYS_DIRECT` (localhost и т.п.), его не перебивает ничто.

Порядок проверки в `decide()`: `ALWAYS_DIRECT` → force `+VPN` → force `−VPN` →
обычная логика режима с учётом `soft`-правил своего списка.

## Синхронизация

Каждый браузер/канал (Chrome, Chrome Dev, Chrome Canary, Opera*, Firefox,
Firefox Dev) — отдельный профиль со своим `storage.local`, между ними ничего
не синхронизируется само по себе. Вместо `storage.sync` — свой сервер:

- `server/sync-server.mjs` — минимальный HTTP-сервер (без зависимостей и БД),
  хранит один JSON-файл `{ rules, updatedAt }`, отдаёт и принимает его по
  Bearer-токену на `/rules`. Запуск: `pnpm run sync-server` (нужен
  `OCSWITCH_SYNC_TOKEN` в окружении).
- `core/src/sync.ts` — клиент (`pullRules`/`pushRules`/`isRemoteNewer`),
  только `fetch()`, без chrome/browser API, поэтому живёт в `core`.
- Модель: «Сохранить» в options пушит правила на сервер, если синхронизация
  включена (`Settings.sync.enabled`). Фон каждого браузера подтягивает
  правила при старте и по будильнику (`alarms`, раз в 15 минут). Конфликты
  решаются по `Settings.rulesUpdatedAt` — побеждает более новая версия.
  Кнопка «Обновить сейчас» в options делает pull немедленно и безусловно.
- Opera — Chromium-форк, использует тот же `dist/chrome`, но это тоже
  отдельный профиль/хранилище — синхронизация нужна и для него.

## Приватные окна (Firefox)

Firefox не даёт расширению форсировать доступ к приватным окнам через
манифест — только пользователь вручную, через `about:addons` → Подробнее →
«Запускать в приватных окнах». Без этого `browser.proxy.onRequest` для
приватных окон вообще не вызывается — трафик тихо идёт в обход `decide()`.
Попап проверяет это через `browser.extension.isAllowedIncognitoAccess()`
и показывает предупреждение. Chrome/Opera не затронуты: там прокси —
PAC на уровне браузера, приватные окна наследуют его без доп. разрешений.
